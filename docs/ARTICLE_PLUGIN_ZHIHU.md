# 从 IGM 到 DeepSeek Harness：给 Agent 记忆装上"写入层"

## IGM 是什么

IGM（Importance-Gated Memory，重要性门控记忆）是我在做 Agent 记忆研究时设计的一套机制。核心问题很朴素：**Agent 应该记住什么？**

现在的记忆方案大多在解决"存了之后怎么找回来"（检索），却几乎不回答两个更基础的问题：

1. **什么值得存？**
2. **存的东西过时了怎么办？**

IGM 的答案是：**记忆不该全存，也不该只增不减。** 它由三个机制组成：

### 1. 重要性闸门

不是什么都往记忆里写。每条候选记忆先打分，只有超过阈值的才写入。打分器是可学习的——用"我的X是Y"这类事实句当正例、闲聊问句当负例训练出来，权重可解释：

| 特征 | 权重 | 含义 |
|---|---:|---|
| 事实密度 | +3.59 | 越像"我的X是Y"越该记 |
| 第一人称 | +2.61 | 关于用户本人的值得记 |
| 是否疑问句 | -4.23 | 问题不是记忆，直接拒绝 |

效果：IGM 用 12 条记忆，达到全量存储 89 条记忆 4 倍的准确率。

### 2. 同属性覆盖（slot supersede）

这是最核心的机制。写入时从"我的X是Y"里抽出属性 X 作为 slot，**同一 slot 的新值直接取代旧值**：

```
我的住址是北京      → slot=住址, 值=北京
我的住址现在是深圳  → slot=住址, 值=深圳（北京被覆盖，不残留）
```

旧值在写入那一刻就消失了，矛盾根本不产生。

### 3. 遗忘（consolidate）

长期没被复用、又没价值的旧记忆，定期自动消退——记忆只增不减会让存储膨胀，也让检索变慢变噪。

## 为什么需要它：RAG 的"写入层"缺口

现在做记忆的主流是 RAG：全量存进向量库，用时检索。RAG 解决了"读"，但**从不过问"写"**——存什么、怎么更新、旧的怎么办。

在标准 RAG 的向量库里，"住北京"和"住深圳"是两条平级向量，没有新旧关系。检索时它俩语义几乎一样，RAG 架构里根本没有"覆盖"这个概念。

我用对照实验验证了这一点——同一个属性连续更新 5 次（新旧值语义近似，如 蓝→青→蓝绿→绿→紫），然后问"当前值"：

| 方法 | 准确率 | 记忆用量 |
|---|---:|---:|
| 标准 RAG（全量存储，信检索第一名） | **0%** | 28 条 |
| 标准 RAG + 时间排序（公平补救） | 60% | 28 条 |
| **IGM 写入层（slot 覆盖）** | **100%** | **4 条** |

标准 RAG 即使用了"按时间取最新"这个最强补救，还是答错——因为按时间排序的前提是先**检索到**目标属性，而 BGE 在 top-3 里把最新值漏了。IGM 用 1/7 的记忆做到全对：**它压根不存旧值**。

## 在 DeepSeek Harness 里落地

研究结论要变成真实可用的东西，我把它做成了 DeepSeek Harness（DSH）的一个插件：`dsh-igm-memory`。

### 插件提供了什么

| 能力 | 实现 |
|---|---|
| 写（闸门 + 覆盖） | `remember_fact` 工具 |
| 读 | `recall_fact` 工具 |
| 跨会话 | 会话启动注入（system-prompt/assemble） |
| 持久化 | JSON 文件（重启不丢） |
| 遗忘 | consolidate 服务 |
| 隔离 | 多 profile 各自独立记忆文件 |

### 真实端到端测试

我在 DSH 里跑完了完整流程：

```
会话 1: "记住我的住址是北京"
        → agent 调 remember_fact，记忆: [住址: 北京]
会话 1: "改记住是深圳"
        → agent 调 remember_fact，旧值覆盖，记忆: [住址: 深圳]
会话 2 (全新会话): "我住址是哪？"
        → 会话启动注入 → agent 答: "你的住址现在是深圳"
```

关键在最后一步：**全新会话**没有上一段对话记录，却直接答对"深圳"——因为注入的持久化记忆里只有当前值（北京已被覆盖）。这复现了受控实验中的“旧值被覆盖、只保留当前值”行为；它不是对所有 RAG 系统效果的结论。


## 怎么用

```sh
dsh plugin --profile web add https://github.com/Stringadmin/dsh-igm-memory
dsh web    # 重启加载
```

装完直接说"记住我的住址是北京"，agent 就会用 `remember_fact` 存进去。

## 一些诚实的边界

- 重要性打分是启发式 + 轻量学习，复杂事实（比如带否定、条件、时间的）可能抽不准 slot。
- 记忆是 JSON 文件存储，单机够用；大规模多用户需要接外部存储。
- 只做了中文 slot 提取（"我的X是Y"句式），英文事实目前不覆盖。
