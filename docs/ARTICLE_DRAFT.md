# 我试图让 AI 学会"不遗忘"，撞了三次墙后搞明白的三件事

> 副标题：从持续学习到 Agent 记忆，一条被我踩出来的统一主线——**约束，要下在执行/写入层，而不是信号/读取层。**

## 写在前面

过去几个月，我一直在研究同一个问题的三个变种：**怎么让 AI 系统在学习新东西的时候，别把旧东西忘掉？**

我先在**参数**层面做（持续学习里的灾难性遗忘），撞了一堵墙；换到**优化**层面接着做，又撞了一堵；最后把同样的思路搬到 **Agent 记忆**上，第三次撞墙。

但奇怪的是，三次撞墙撞出了一条我从没想过的主线。这条主线不是"我提出了一个新方法，刷了多少点"——我没有。它是三个**反复被验证、但很少被人系统讲清楚**的教训。

这篇文章没有 SOTA，没有刷榜，只有三次实验的真实数据、能直接跑起来的复现命令，和一条我现在深信不疑的结论：

> **想让系统"记住"，关键从来不在"怎么感知/读取"（信号层），而在"怎么强制执行/写入"（执行层）。**

如果你正在做持续学习、Agent 记忆、或者任何涉及"选择性保留"的系统，希望我撞过的墙能让你少走点弯路。

---

## 第一堵墙：我以为冻结了梯度，参数就不会动

### 背景

第一个项目叫 FIP，目标是持续学习里的**灾难性遗忘**：一个 Transformer 依次学多个任务，怎么让它学第 N 个任务时不把前 N-1 个忘掉？

我的思路在当时看来很自然：**既然遗忘是参数被新任务的梯度改写了，那把承载旧知识的参数"冻结"不就行了？**

具体做法是给每个参数算一个"重要性"，把重要的标记为 `stable`，然后在反向传播时用**梯度 hook** 把这些参数的梯度清零。梯度是零，参数自然不会更新，旧知识就保住了。逻辑闭环，无懈可击。

我还给它配了一整套机制：Top-K 稀疏激活、特征状态机（stable/shared/plastic/free）、任务结束时按重要性固化。代码写完，21 个单元测试全过，我很满意。

### 撞墙

然后我跑了一个 sanity check：故意冻结一批参数，只清零梯度，训练几十步，再去看这些参数**到底有没有动**。

动了。

| 冻结方式 | 冻结参数的最大漂移 |
|---|---:|
| 梯度 hook（梯度清零） | **9.94e-05** |
| 我期望的 | 0 |

不是 bug。我盯着代码看了很久才想明白一个**教科书不会强调、但极其要命**的事实：

**AdamW 不是靠梯度更新的。**

- **解耦权重衰减（decoupled weight decay）**：每一步都会直接对参数乘一个 `(1 - lr × weight_decay)` 的因子，**和梯度是不是零完全无关**。梯度为零，权重衰减照样把参数往零拉。
- **历史动量（momentum / variance）**：Adam 里存着过去梯度的指数滑动平均。就算当前梯度是零，只要历史动量非零，参数就会被这股"惯性"继续推动。

也就是说，我精心设计的"梯度清零"，冻结的只是**梯度**，而参数被**另外两股力量**悄悄地、持续地挪动。我以为我把门锁了，其实小偷是从窗户进去的。

### 解法：在执行层动手，而不是信号层

想明白之后，解法反而简单了：**别去拦梯度（信号），直接在优化器更新完之后，对参数的实际增量（delta）做投影。**

我写了一个 `FeatureMaskedAdamW`，在 `optimizer.step()` 之后加一步：

```
parameter_after = parameter_before + mask × (adamw_step 算出的增量)
```

`stable` 参数的 mask = 0，于是**无论 AdamW 内部怎么折腾，stable 参数的最终增量被强制归零**。顺手再把它们的 Adam 动量清零，斩草除根。

再跑 sanity check：

| 冻结方式 | 冻结参数的最大漂移 |
|---|---:|
| 梯度 hook（信号层） | 9.94e-05 |
| **优化器 delta 投影（执行层）** | **0.00e+00** |

这次是真的冻住了。

### 这件事教会我的第一件事

> **"我以为我控制了它"和"我真的控制了它"，差着一个执行层。**

信号（梯度）只是优化的一个输入。真正决定参数命运的，是优化器内部那一整套你看不见的状态（动量、方差、权重衰减）。**想强制执行一个约束，必须在约束真正生效的那一层动手。**

这个教训，我当时以为只适用于 AdamW。后来我才发现，它是一个普遍规律。

## 第二堵墙：机制全对，但就是打不过简单粗暴的基线

### 背景

修好了"冻结"的问题，我把完整的 FIP 跑起来，和一堆基线对比：普通全量微调、EWC、5% 经验回放、稀疏微调。协议是提前冻结的，6 个可控合成任务，等 token、等步数、等学习率。

### 撞墙

结果让我很难堪：

| 方案 | 平均遗忘（越低越好） |
|---|---:|
| E 稀疏全量微调（基线） | 0.456 |
| F FIP（我的方法） | 0.492 |
| C 5% 经验回放（最强基线） | 0.253 |

**我的 FIP 比"什么都不加的稀疏微调"还要差。** 门槛是"比基线降 50%"，我不但没降，还更差了。

我不死心，顺着诊断往下挖，发现遗忘的主战场根本不在我严防死守的 FFN 参数，而在 embedding、attention、norm 这些我没管的地方。于是我把"重要性保护"扩展到所有非 FFN 参数（这个项目改叫 GPP），这次确实有效——遗忘降到 0.312，而且新任务学习能力 100% 保留。

但即便如此，**在另一个更简单的基准上，GPP 依然只是"边际改善"，打不过"BGE 嵌入 + 全量微调"这种简单粗暴的组合**。而且结果对训练步数、学习率极度敏感——1000 步全崩，400 步才有点优势。

### 这件事教会我的第二件事

> **一个精巧的机制，只有在它解决的问题是真正的瓶颈时，才有价值。**

我的机制（重要性驱动的选择性保留）是对的——后来的消融证明，用"智能分配"比"随机分配"好 25.7%。但它解决的"FFN 参数遗忘"在这个任务里不是主因。我在一个不是瓶颈的地方，造了一把精巧的锁。

这是做研究最容易掉的坑：**你爱上自己的机制，于是你到处找它能解决的问题，而不是先看问题真正的瓶颈在哪。**

## 第三堵墙：搬到 Agent 记忆，同样的剧情又演了一遍——但这次我看懂了

### 背景

前两次撞墙后，我注意到一个事：**"选择性保留"这个问题，不只存在于参数空间。**

2026 年的 Agent 都在被同一个问题折磨——**记忆**。上下文窗口一满就忘，跨会话什么都不记得。

现在做记忆，主流叙事就是 **RAG**：把对话全塞进向量数据库，用的时候按语义相似度检索。Letta、Mem0、Zep 本质上都是 RAG 的变种——它们的区别在于怎么组织存储（向量 / 知识图谱 / 分层），但**写入策略都是同一个：默认全存，或让 LLM/规则简单提取后全存。**

而今年的基准研究（BEAM, ICLR 2026）已经证明了一个反直觉的结论：

> **长上下文 ≠ 长记忆。** 把上下文堆到 100 万 token，模型照样退化。真正难的是**知识更新**和**矛盾解决**——用户改了个事实，系统得忘掉旧值、用上新值。

这里有个被所有人忽略的点：**RAG 解决的是"存了之后怎么找回来"（读），但它从不回答"什么值得存"和"存的东西过时了怎么办"（写）。**

在标准 RAG 的向量库里，"用户住北京"和"用户现在住深圳"是**两条独立的向量**，彼此没有任何新旧关系。检索时它们语义几乎一样，RAG 的架构里**根本没有"覆盖"这个概念**——它不知道哪条该被淘汰。

我看到"矛盾解决"这四个字的时候，DNA 动了。**这不就是参数空间里的"灾难性遗忘"，换了个壳吗？** 于是我把前两次踩出来的那套"重要性驱动 + 选择性保留 + 执行层落地"搬到了 Agent 记忆上，做了个项目叫 IGM。

要先说清楚：**IGM 不是来替代 RAG 的。它是装在 RAG 前面的"写入层"**——RAG 管读（检索），IGM 管写（筛选 + 覆盖）。你完全可以把它接在任何现有 RAG 系统前面：

![标准 RAG 与 IGM 写入层架构对比](fig1_rag_vs_igm.png)

可以看到，向量库和检索那一端完全没变——IGM 动的只是"写进去什么"。

### IGM 做了什么

和前面一脉相承，三件事：

1. **写入闸门**：不是什么都记。给每条候选记忆算一个"重要性"，只有重要的才写入。这个重要性是用**可学习的打分器**算的——我用手写规则生成了弱监督标签（"我的X是Y"是事实=正例，闲聊是负例），训练了一个 logistic 回归。学到的权重**高度可解释**：

   | 特征 | 权重 | 含义 |
   |---|---:|---|
   | 事实密度（是不是"我的X是Y"） | +3.59 | 最强正信号 |
   | 第一人称（"我"） | +2.61 | 关于用户的才值得记 |
   | 是否疑问句 | **-4.23** | 最强负信号：问题不是记忆 |
   | bias | -2.28 | 默认不写入（高阈值） |

   结果：**IGM 用 12 条记忆，达到了全量存储 89 条记忆 4 倍的准确率。** 写入闸门有效。

2. **slot 覆盖（关键创新）**：写入时从"我的X是Y"里抽出属性 X 当作 slot，**同 slot 的新值直接取代旧值**。知识更新场景下，准确率从 0 提到 1.0。

3. **执行层兜底**：检索时不只靠向量相似度，还按 slot 精确路由。

### 撞墙（熟悉的剧情）

我兴冲冲地拿它和一个**标准 RAG 流水线**对比——BGE 嵌入 + 全量写入（不筛选、不覆盖，全记下来，靠最强的中文嵌入检索）。这就是你随便用一个向量数据库 + 一个好嵌入搭出来的记忆系统，也是现在绝大多数 Agent 的实际做法。

在简单场景下，我又输了。BGE 太强了，**标准 RAG 全量存储也能答对几乎所有问题**，我的"少而精"毫无精度优势，只剩"省内存"这个没人关心的卖点。

这里我得诚实：**如果你的场景 RAG 全量存储就能搞定，那 IGM 的精巧就是多余的。** 这不是 RAG 的错，是我不该在 RAG 的主场（简单事实召回）跟它硬碰。第三次撞墙，撞的还是同一个道理——别在对手足够好的战场上打架。

### 但这次，我找到了那个"RAG 必输"的场景

前两次我都在"基线够好"的战场上硬碰硬，输得不冤。这一次我决定**设计一个标准 RAG 在原理上就不可能赢的场景**，看看 IGM 补的那层"写入"到底是不是真本事。

场景：**同一个属性被连续更新 5 次，而且新旧值语义上几乎一样。** 比如"最喜欢的颜色"，从蓝色 → 青色 → 蓝绿色 → 绿色 → 紫色，一路改。然后问："我现在最喜欢什么颜色？"

- **标准 RAG（全量写入）**：把 5 个历史值全存进向量库。检索时，"蓝色/青色/蓝绿色/绿色/紫色"这几个值在嵌入空间里**几乎重叠**——BGE 再强，也分不清哪个是"最新"。更要命的是，RAG 的向量库里这 5 条是**平级的**，没有任何"谁取代谁"的信息，它只能赌。
- **IGM（写入层做覆盖）**：slot 覆盖只保留最新的"紫色"，根本不存旧值，所以不会错。

为了让 RAG 公平，我特意给它两个版本：一个"信检索第一名"，一个"按时间戳取最新"（给向量库的每条记录加个时间字段，检索后按时间排序——这是 RAG 系统能做到的最强补救）。而且**整个评估不调用 LLM 来回答**——直接用规则读取记忆返回的值，把 LLM 的推理噪音彻底排除，测的纯粹是记忆/RAG 层本身。

结果（BGE 嵌入，11 秒跑完，完全可复现）：

![决定性实验：连续更新场景下三种方法的准确率与记忆用量](fig2_decisive_experiment.png)

**标准 RAG 即使用了"按时间排序"这个最强补救，还是错了**——因为按时间排序的前提是先**检索到**目标属性，而 BGE 在 top-3 里把目标属性的最新值漏了。

而 IGM 用 **1/7 的记忆（4 条 vs 28 条）做到 100%**。它赢不是因为检索更聪明——它用的还是同一个向量库、同一个 BGE——而是因为**它在写入那一刻就把旧值覆盖了**。读的能力没变，变的是写进去的东西。

### 这件事教会我的第三件事

> **RAG 解决了"读"，但没解决"写"。矛盾解决的钥匙，在写入层。**

你注意到了一个完美的呼应吗？

- 第一幕里，**梯度为零**（信号层）挡不住 **AdamW 的动量**（执行层），所以必须在优化器层做 delta 投影。
- 第三幕里，**嵌入相似度**（读取/信号层）分不清**新旧语义近似的值**，所以必须在**写入层**做覆盖——别让旧值进库，而不是指望读的时候把它们区分开。

**两次都是同一个教训：读取/信号这一层是有极限的，而那个极限，只能靠"写入/执行"那一层的硬约束来兜底。**

换句话说：**别再拼命优化检索（读）了。很多问题，答案在写入（写）那一侧。** RAG 的向量库和嵌入已经够好了，缺的是一个聪明的写入策略——什么该存、什么该覆盖、什么该忘掉。

## 撞了三次墙，我搞明白的三件事

把三幕串起来，就是这篇文章真正想说的：

### 1. "我以为控制了" ≠ "我控制了"——约束要下在执行层

梯度 hook 冻不住参数，因为 AdamW 靠动量和权重衰减更新。RAG 检索分不清新旧，因为语义近似的值在向量空间重叠。**任何"选择性保留"的系统，都要问自己一句：我的约束是下在了"感知/读取"的那一层，还是"真正生效/写入"的那一层？** 几乎所有人都下错了层。

### 2. 机制没有绝对的好坏，只有"是否打在瓶颈上"

我的重要性保留机制，在 FFN 参数上输了（不是瓶颈），在非 FFN 参数上赢了（是瓶颈），在简单记忆场景输了（RAG 全量存储够好），在矛盾解决场景赢了（RAG 必输）。**同一个机制，四场战役，两胜两负。** 别爱上你的锤子，先看钉子在哪。

### 3. "重要性驱动的选择性保留"是一个可迁移的范式

这是我最大的收获。从参数（FIP/GPP）到记忆（IGM），同一个范式反复出现：

> **用重要性信号筛选 → 在执行/写入层强制保留或淘汰 → 让系统随时间只积累真正重要的东西。**

它可以是优化器里的 delta 投影，也可以是 RAG 写入层的 slot 覆盖。形式不同，但内核是同一个：**感知重要性是辅助，强制执行才是本体。**

## 一些诚实的边界

我不想把这写成"我搞了个厉害的东西"，所以必须说清楚它**什么时候没用**：

- **标准 RAG 就够用时，别加这层。** 如果你的场景 RAG 全量存储 + 强嵌入就能 90%+，那 IGM 的写入层就是多余的复杂度。它的价值只在"RAG 全量写入会崩"的地方——大规模、频繁更新、需要矛盾解决的场景。
- **读取层能解决的问题，别动写入层。** 如果你只是检索不准，换个好嵌入、调调 top-k 就行，犯不着搞覆盖机制。IGM 解决的是"读没问题、写错了"的病。
- **IGM 是 RAG 的增强件，不是替代品。** 它复用同一个向量库、同一个嵌入，只是在写入侧加了筛选和覆盖。你不需要推翻现有 RAG 系统，把它接在前面就行。
- **这些实验是在受控合成数据上做的**，模型是 4B 的本地模型，不是 GPT-4。结论的方向我有信心，但绝对数字别当真——在真实大规模数据上，所有方法的表现都会变。

我没能做出一个刷榜的系统。但撞了这三堵墙之后，我对"怎么让 AI 记住东西"这件事的理解，比我开始时深了不止一个层次。

如果你也在做类似的东西，希望这三堵墙对你有用。**别只在读取/信号层雕花了，去写入/执行层下硬约束。** 这是我用三次失败换来的，你免费拿去。
