# 受控更新记忆：公平消融与负载扫描

> 日期：2026-08-20  
> 状态：受控合成实验。它验证明确的状态/版本语义，不证明 IGM 在通用 RAG、LongMemEval 或真实 Agent 上更准确。

## 先给结论

之前仅用 5 条手工更新链，不能作为有说服力的性能证据。扩展后的 500 条 BGE 随机化链也**没有**显示 IGM 比一个有属性字段、按时间取最新值的版本库更准：两者当前值都是 `500 / 500`。

这个结果回答了“全量也是 100%，IGM 的意义是什么”：

- 若产品要回答历史版本，保留全部版本并在读取时按 `attribute + timestamp` 处理已经足够，IGM 没有准确率优势。
- 若产品只需要当前状态，IGM 在这个负载下少保留 4 个被覆盖的旧版本（`32 -> 28`），并让向量检索不必携带互相矛盾的版本。
- 代价不能回避：同一实验里，版本库回答“上一次是什么”的正确率是 `500 / 500`，IGM 是 `0 / 500`，因为它刻意删除旧值。

因此这里能支持的说法是：**更新型记忆必须明确选择“保留版本”还是“压缩为当前状态”**。IGM 是后者的一种实现，不是全量 RAG 无法做到的能力。

随后实现的 Versioned IGM 不再要求二选一：它保留门控后的版本事件库，并以事件引用构建当前状态视图。两个 BGE seed 上当前值与历史值均为 `500 / 500`。这修复了破坏性覆盖的功能缺口，但不构成对版本化 RAG 的准确率胜利；详见 [Versioned IGM 架构与验证](VERSIONED_IGM_ARCHITECTURE.md)。

## 设置

每条会话有一个属性的 5 次更新，4 条闲聊插在每次更新前；另有 3 条固定事实和 24 条不冲突的长期背景事实。原始输入为 52 个 turn。问题分为两类：

1. 当前问题：`我现在的 X 是什么？`
2. 历史问题：`X 上一次是什么？`

随机化条件从 5 个属性、每属性 20 个预定义候选值中无放回抽取 5 个值，按 seed `1337` 与 `42` 各生成 500 条链。所有方法读取完全相同的原始 turn；底层均为 BGE-small-zh，答案由规则读取记忆，以隔离存储与检索行为，不引入 LLM 推理随机性。

| 方法 | 写入 | 当前问题读取 | 历史问题读取 |
|---|---|---|---|
| 原始全量 | 每个 turn | BGE top-1 / top-3 后取最新 / 属性+时间 | 属性+时间取倒数第二版 |
| 门控但保留版本 | 与 IGM **同一轮、同一分数**的写入决定 | 同上 | 同上 |
| IGM | 同一门控；同 slot 新值覆盖旧值 | slot 路由 | 不支持，旧版本已删除 |
| Versioned IGM | 同一门控；事件追加 + 当前 slot 引用 | 当前视图按 slot 解引用 | 事件库按 slot 取版本线 |
| FIFO 对照 | 原始全量或门控版本，容量达上限后丢最旧 | 同上 | 可能因淘汰失败 |

“门控但保留版本”是关键消融：它和 IGM 共用抽取器、写入门槛、相同的 BGE，以及逐 turn 的同一门控决定；唯一差异是是否覆盖同 slot 的旧版本。

## 500 条随机化结果

下表显示 seed `1337 / 42`。括号内是成功数，不把两个 seed 合并成 1,000 个独立真实样本。它们共享模板、属性和背景事实，只能用于稳定性检查。原始 JSON 还写出 Wilson 区间，作为描述性审计信息，**不可**当作真实用户分布上的显著性推断。

| 方法 | 当前值，1337 | 当前值，42 | 历史值，1337 | 历史值，42 | 持久化事件/记录 | 当前投影 |
|---|---:|---:|---:|---:|---:|---:|
| 原始全量，BGE top-1 | 22.8% (114/500) | 23.2% (116/500) | - | - | 52 | 52 |
| 原始全量，top-3 + 时间 | 66.8% (334/500) | 71.4% (357/500) | - | - | 52 | 52 |
| 原始全量，属性 + 时间 | 100% (500/500) | 100% (500/500) | 100% | 100% | 52 | 52 |
| 门控但保留版本，属性 + 时间 | 100% (500/500) | 100% (500/500) | 100% | 100% | 32 | - |
| 破坏性 IGM，slot 覆盖 | 100% (500/500) | 100% (500/500) | 0% | 0% | 28 | 28 |
| **Versioned IGM，事件 + 当前视图** | **100% (500/500)** | **100% (500/500)** | **100%** | **100%** | **32** | **28 个事件引用** |

固定 28 条容量下的背景事实检查也说明这个差异很窄：原始 FIFO 只能召回 `12.5%`（3/24），而门控 FIFO 为 `95.8%`（23/24），IGM 为 `100%`（24/24）。每条链都重复了相同 24 条背景事实，所以 12,000 个检查不是 12,000 个独立事实。

原始结果：

- `reports/memory-decisive-random500-bge.json`（seed 1337）
- `reports/memory-decisive-random500-bge-seed42.json`（seed 42）
- `reports/memory-versioned-igm-random500-bge.json`（Versioned IGM，seed 1337）
- `reports/memory-versioned-igm-random500-bge-seed42.json`（Versioned IGM，seed 42）

## 复现

```bash
# 可读的 5 链示例
python -m memory_arch.run_decisive --embed-backend bge \
  --background-facts 24 --full-capacity 28 \
  --output reports/memory-decisive-cap28.json

# 500 条随机化机制负载（真实 BGE；不调用 LLM）
python -m memory_arch.run_decisive --embed-backend bge \
  --background-facts 24 --full-capacity 28 \
  --random-trials 500 --updates-per-chain 5 --seed 1337 \
  --output reports/memory-decisive-random500-bge.json
```

## 不能据此声称什么

- 值和句式来自手工池；slot 解析器正是针对 `我的 X 是 Y` / `我的 X 现在是 Y` 的中文模板写的。它不评估复杂语言、否定、条件、时间限定或抽取错误。
- 500 条链不是 500 位用户，也不是独立的自然语言样本；共同的背景事实与有限候选池会放大稳定性。
- 当前值问题天然偏向状态压缩；历史问题天然偏向版本库。应先按产品需求选择语义，再比较成本。
- 条目数不是 token、字节、索引延迟、写入延迟或端到端 Agent 成功率。此次没有测这些成本。
- FIFO 只是一种容量策略；仍缺少 LRU、TTL、真实 upsert/versioned vector DB 和 LongMemEval/真实匿名日志的对比。
