# 结果反馈记忆：从保存事实到修正经验

> 状态：实验原型已验证；尚未迁移到 `dsh-igm-memory` 插件，也不修改模型参数。

## 要解决什么

Versioned IGM 解决的是“事实更新后，当前状态和历史版本如何同时保留”。长期运行的 Agent 还需要另一种记忆：它做过某个动作后，结果是成功还是失败；当环境变化，新的失败是否能推翻旧的成功经验。

这里的“学习”是**外部记忆驱动的行为适应**，不是在线训练模型权重。RAG 仍然有位置：它可帮助把当前任务映射到情境、找出候选经验；本层负责把执行结果变成可审计的证据，并根据证据推荐动作。

```text
任务 + RAG/规则提供的情境与候选动作
  -> 执行动作
  -> 成功/失败、时间、来源
  -> append-only OutcomeEvent archive
  -> (情境, 动作) 的衰减成功/失败证据视图
  -> 推荐当前证据最强的动作

复盘/审计 -> 读取完整 OutcomeEvent 历史
```

`OutcomeMemory` 保留每个不可变 `OutcomeEvent`，同时维护一个物化证据视图。对同一 `(context, action)`，成功和失败的权重会按 `exp(-decay_rate * elapsed_time)` 衰减；推荐使用带 Beta 先验的成功率后验。新结果改变当前推荐，但不删除旧结果，因此后续可审计，也可以改用别的衰减策略重算。

## 受控验证：概念漂移后的经验修正

实验位于 `memory_arch/run_outcome_drift.py`。它没有调用 LLM 或嵌入模型，目的是只验证结果反馈的记忆语义：

- `200` 个随机 seed，每个 seed 有 `32` 个独立情境和两个候选动作。
- 先经历 `12` 轮稳定环境，再让每个情境的最优动作全部翻转，继续 `12` 轮。
- 最优动作每次成功概率为 `0.85`，非最优动作是 `0.15`。
- 每轮都观察两个动作的结果。这是**全信息**设置，刻意排除了“只能执行一个动作时如何探索”的难题。
- 输出为规则推荐是否等于当前真实最优动作；它不是模型回答质量或真实 Agent 端到端成功率。

| 方法 | 稳定阶段准确率 | 漂移后平均准确率 | 漂移第 12 轮 | 达到 80% 的轮数 |
|---|---:|---:|---:|---:|
| 最近一次结果 | 84.79% | 84.96% | 84.56% | 1 |
| 全历史等权平均 | 97.81% | 12.99% | 50.06% | 未达到 |
| 仅保留衰减统计的等价基线 | 97.67% | 82.39% | 99.77% | 4 |
| **OutcomeMemory（事件归档 + 证据视图）** | **97.67%** | **82.39%** | **99.77%** | **4** |

每个 seed 的 `OutcomeMemory` 保留 `1536` 个结果事件（`32` 情境 × `2` 动作 × `24` 轮），当前证据视图仅有 `64` 个 `(情境, 动作)` 键。`64` 不是总存储量，事件归档仍然存在。

原始结果：`reports/outcome-feedback-drift.json`。

## 部分反馈验证：必须靠探索获得结果

前面的全信息实验没有模拟真实 Agent 的一个硬约束：它通常只能看到**自己实际执行**的工具调用或方案的结果。为此增加了 `memory_arch/run_outcome_bandit.py`：每轮每个情境只能选择一个动作，只有这个动作的成功/失败写入记忆；选择策略为 10% epsilon-greedy 探索，环境与成功概率仍与上面的实验一致。

- `400` 个随机 seed，`32` 个情境，稳定阶段和翻转阶段各 `20` 轮。
- 每个策略独立维护自己的记忆，只能读取自己选中动作的反馈。
- 模拟器为保证比较方差更小，会预先生成两个动作的结果；策略绝不会读取未执行动作的那一格结果。
- 指标同时报告“是否选到当前最优动作”和真实观察到的成功率；两者在有噪声时不同。

| 方法 | 稳定阶段动作准确率 | 漂移后平均动作准确率 | 漂移第 20 轮动作准确率 | 漂移第 20 轮成功率 | 达到 80% 的轮数 |
|---|---:|---:|---:|---:|---:|
| 随机、无记忆 | 49.95% | 49.91% | 50.34% | 50.48% | 未达到 |
| 全历史等权平均 | 86.20% | 18.21% | 35.41% | 39.35% | 未达到 |
| 仅保留衰减统计的等价基线 | 89.65% | 78.65% | 93.60% | 80.80% | 6 |
| **OutcomeMemory（事件归档 + 证据视图）** | **89.65%** | **78.65%** | **93.60%** | **80.80%** | **6** |

每个 seed 的 OutcomeMemory 保存 `1280` 个执行结果事件（`32 × 40`），并实际形成 `64` 个证据键。等价基线再次得到逐步完全一致的决策：表现来自衰减证据和探索策略，事件归档只增加审计与重算能力。原始结果：`reports/outcome-feedback-bandit.json`。

## 污染反馈验证：来源标签必须进入证据权重

部分反馈仍有安全问题：一次工具调用的“成功”可能来自失效监控、错误解析或不可信输入。`OutcomeEvent` 因此记录不可变的 `provenance` 与 `evidence_weight`；低可信事件不会被删除，但只按较小权重进入当前证据视图。

`memory_arch/run_outcome_poison.py` 在部分反馈负载上加入一项**明确标记**的污染条件：每个被观察结果有 30% 概率被反转，并标为 `unverified_report`，权重为 `0.05`；其余为 `verified_execution`，权重为 `1.0`。未加权组接收完全相同的报告和标签，但有意忽略标签。每个策略仍只看到自己执行动作的报告。

| 方法 | 稳定阶段动作准确率 | 漂移后平均动作准确率 | 漂移第 20 轮动作准确率 | 漂移第 20 轮真实成功率 | 达到 80% 的轮数 |
|---|---:|---:|---:|---:|---:|
| 随机、无记忆 | 49.97% | 49.99% | 49.73% | 49.71% | 未达到 |
| 衰减证据，但忽略来源标签 | 71.33% | 65.05% | 75.41% | 68.17% | 未达到 |
| 仅保留来源加权统计的等价基线 | 85.64% | 76.59% | 91.11% | 78.95% | 7 |
| **来源加权 OutcomeMemory** | **85.64%** | **76.59%** | **91.11%** | **78.95%** | **7** |

每个 seed 保留 `1280` 个结果事件和 `64` 个证据键。来源加权的等价统计基线再次与 OutcomeMemory 完全一致：这验证的是**正确的来源标签可以限制已知低可信反馈的影响**，而不是事件库自动发现了错误或提示注入。若攻击者能伪造为 `verified_execution`，或可靠来源本身错误，实验给不出任何防护保证。原始结果：`reports/outcome-feedback-poison.json`。

## 结论与边界

实验支持的结论很窄：**在有噪声、规则发生翻转、并且能获得结果反馈的受控任务中，按时间衰减的证据可让当前经验逐步推翻陈旧经验；完整事件归档不会阻碍该适应。**

它不支持以下说法：

- OutcomeMemory 比所有在线学习、RAG 或 Agent 框架更准。
- 事件归档本身比“只保留衰减统计”更会预测。等价基线的结果刻意完全一致；事件归档的价值是审计、解释、回放和重算。
- Agent 已经自主训练或接近 AGI。模型权重没有改变；真实任务还存在探索、因果混杂、奖励投机、错误反馈和安全审批问题。

来源权重应只来自可验证的系统边界，例如经过签名的测试结果、受控监控或人工审核；不能根据模型生成文本的语气自动赋予高信任。可信度配置本身也需要版本化、审计和最小权限控制。

对于生产 Agent，只有具备可信的结果信号时才应写入这类经验，例如测试通过、部署回滚、用户明确纠正或经过人工审核的 KPI。高风险动作还需要把证据来源、权限范围、置信度和人工批准作为事件字段，不能直接把一次成功当成通用规律。

## 复现

```bash
python -m memory_arch.run_outcome_drift \
  --seeds 200 --contexts 32 \
  --stationary-rounds 12 --drift-rounds 12 \
  --success-probability 0.85 --decay-rate 0.28 \
  --output reports/outcome-feedback-drift.json

# 部分反馈：每轮只能观察自己执行动作的结果
python -m memory_arch.run_outcome_bandit \
  --seeds 400 --contexts 32 \
  --stationary-rounds 20 --drift-rounds 20 \
  --success-probability 0.85 --decay-rate 0.28 --exploration-rate 0.10 \
  --output reports/outcome-feedback-bandit.json

# 明确标记的污染反馈：验证来源权重的条件性防护
python -m memory_arch.run_outcome_poison \
  --seeds 400 --contexts 32 \
  --stationary-rounds 20 --drift-rounds 20 \
  --success-probability 0.85 --decay-rate 0.28 --exploration-rate 0.10 \
  --corruption-rate 0.30 --untrusted-weight 0.05 \
  --output reports/outcome-feedback-poison.json
```

## 下一步门槛

部分反馈模拟仍不是端到端 Agent。迁入插件前，至少要完成一个带真实工具调用的基准：让 Agent 在多轮任务中只观察自己实际执行的结果，比较无记忆、追加经验、版本化经验和衰减证据，并报告任务成功率、错误动作率、恢复速度、prompt token、持久化字节、p95 延迟及错误经验污染率。只有这些结果稳定，才值得把 `OutcomeMemory` 接到真实写入工具上。
