# 从 IGM 到 DeepSeek Harness：给 Agent 记忆装上"写入层"

## IGM 是什么

IGM（Importance-Gated Memory，重要性门控记忆）是我在做 Agent 记忆研究时设计的一套机制。核心问题很朴素：**Agent 应该记住什么？**

现在的记忆方案大多在解决"存了之后怎么找回来"（检索），却几乎不回答两个更基础的问题：

1. **什么值得存？**
2. **存的东西过时了怎么办？**

IGM 的答案是：**记忆不该全存，也不该只增不减。** 它由三个机制组成：

### 1. 重要性闸门

不是什么都往记忆里写。每条候选记忆先打分，只有超过阈值的才写入。打分器是可学习的——用"我的X是Y"这类事实句当正例、闲聊问句当负例训练出来，权重可解释：

| 特征 | 权重 | 含义 |
|---|---:|---|
| 事实密度 | +3.59 | 越像"我的X是Y"越该记 |
| 第一人称 | +2.61 | 关于用户本人的值得记 |
| 是否疑问句 | -4.23 | 问题不是记忆，直接拒绝 |

门控会过滤闲聊、减少写入；它不是通用准确率提升，效果取决于抽取质量、查询类型和容量约束。

### 2. 同属性覆盖（slot supersede）

这是插件的核心机制。写入时从"我的X是Y"里抽出属性 X 作为 slot，**同一 slot 的新值成为唯一当前值**：

```
我的住址是北京      → slot=住址, 值=北京
我的住址现在是深圳  → slot=住址, 值=深圳（北京被关闭有效期，留在归档）
```

矛盾在写入那一刻就被消除：检索、跨项目匹配和会话启动注入都只读当前投影，看不到北京。但旧值不再被删掉——它带着 `validTo` 留在 JSON 归档里。

第一版不是这样：那会儿同 slot 的新值会把旧记录就地改写掉，北京直接消失。这在"只要当前状态"时没问题，一旦抽取器把两个不相关的属性猜成同一个 key，被删掉的那条就永久回不来了。现在改成归档式覆盖，抽取失误最多是把旧值遮住，历史还在。

### 3. 遗忘（consolidate）

长期没被复用、又没价值的旧记忆，定期自动消退——记忆只增不减会让存储膨胀，也让检索变慢变噪。

## 为什么需要它：RAG 的"写入层"缺口

现在做记忆的主流是 RAG：写进向量库，用时检索。成熟系统可以有 upsert、版本和元数据过滤；但最简单的“追加向量 + 语义 top-k”并不自动定义存什么、怎么更新、旧值怎么办。

若直接把“住北京”和“住深圳”追加成两条向量，它们没有新旧关系。除非另加版本字段、时间排序或覆盖规则，检索时两条语义近似记录会并存。

我用受控对照实验检验这个取舍：同一个属性连续更新 5 次（新旧值语义近似，如 蓝→青→蓝绿→绿→紫），同时加入 24 条长期背景事实。500 条随机化链使用 BGE；另加“门控但保留版本”的公平消融，它逐 turn 复用 IGM 的同一门控决定，唯一不做 slot 覆盖。

| 方法（BGE，28 条容量条件） | 当前值（500 条） | 历史值 | 持久化事件/记录 | 当前投影 |
|---|---:|---:|---:|---:|
| 原始全量，语义 top-1 | 22.8% | - | 52 | 52 |
| 原始全量，属性 + 时间 | 100% | 100% | 52 | 52 |
| 门控但保留版本，属性 + 时间 | 100% | 100% | 32 | - |
| 破坏性 IGM（slot 覆盖） | 100% | 0% | 28 | 28 |
| **Versioned IGM（实验原型）** | **100%** | **100%** | **32** | **28 个事件引用** |

结论不是“IGM 比全量 RAG 准”。只要有显式属性和时间语义，版本库也能答对当前值，并且还能回答“上一次是什么”。破坏性 IGM 选择删除旧版本，用 4 条更少的常驻记录换取只表达当前状态。

为验证这个损失是否必须，我又做了 Versioned IGM 原型：门控后的事实写入不可变事件库，当前投影由 `valid_to is None` 的事件派生，并通过 `supersedes` 保留版本关系。它在两个 500 条 BGE seed 上当前值和历史值均为 100%，但仍持久化 32 个事件，不能把"28 个当前引用"宣传成总存储。更关键的是，门控版本库的准确率也相同，一个正常的带二级索引版本库也能直达当前事件。因此它是把状态视图和版本归档封装到同一个接口的工程架构，不是算法胜利。这套语义现在已下沉为 `igm` 库和 DSH 插件的**默认覆盖行为**（旧值关闭有效期进归档，要旧的破坏性覆盖就显式设 `supersede="delete"`），插件另外加了写入信任边界。完整配置和限制在研究仓库的 `docs/MEMORY_DECISIVE_LOAD_SWEEP.md` 与 `docs/VERSIONED_IGM_ARCHITECTURE.md`：500 条仍是模板化合成链，不能外推为真实 Agent 或通用 RAG 结果。

## 在 DeepSeek Harness 里落地

研究结论要变成真实可用的东西，我把它做成了 DeepSeek Harness（DSH）的一个插件：`dsh-igm-memory`。

### 插件提供了什么

| 能力 | 实现 |
|---|---|
| 写（闸门 + 覆盖） | `remember_fact` 工具（被取代的旧值进归档，不删） |
| 读 | `recall_fact` 工具 |
| 读历史 | `recall_history` 工具 / `recall_fact(mode=previous\|history)` |
| 跨会话 | 会话启动注入（system-prompt/assemble） |
| 持久化 | JSON 文件（重启不丢） |
| 遗忘 | consolidate 服务 |
| 隔离 | 多 profile 各自独立记忆文件 |
| 写入信任边界 | 提示控制指令隔离待审、凭证形态直接拒写；`audit` / `review` 只给宿主 |

### 真实端到端测试

我在 DSH 里跑完了完整流程：

```
会话 1: "记住我的住址是北京"
        → agent 调 remember_fact，记忆: [住址: 北京]
会话 1: "改记住是深圳"
        → agent 调 remember_fact，北京被关闭有效期进归档，当前视图: [住址: 深圳]
会话 2 (全新会话): "我住址是哪？"
        → 会话启动注入 → agent 答: "你的住址现在是深圳"
```

关键在最后一步：**全新会话**没有上一段对话记录，却直接答对"深圳"——因为注入的持久化记忆里只有当前值（北京已归档，不再进入读路径）。这复现了受控实验中的"只保留当前值"行为；它不是对所有 RAG 系统效果的结论。


## 怎么用

```sh
dsh plugin --profile web add https://github.com/Stringadmin/dsh-igm-memory
dsh web    # 重启加载
```

装完直接说"记住我的住址是北京"，agent 就会用 `remember_fact` 存进去。

## 一些诚实的边界

- 重要性打分是启发式 + 轻量学习，复杂事实（比如带否定、条件、时间的）可能抽不准 slot。
- 记忆是 JSON 文件存储，单机够用；大规模多用户需要接外部存储。
- 只做了中文 slot 提取（"我的X是Y"句式），英文事实目前不覆盖。

---

记忆系统的关键不只是“存得更多”或“删得更干净”，而是先说明产品需要当前状态、版本历史，还是两者兼有，再让写入与读取语义和这个选择一致。
