# GPP M0 机制门控报告

> 日期：2026-08-10
> 状态：H4 通过；H1 机制有效但未稳定达标（3 种子平均 0.296 > 门控 0.2278）
> 提案：`docs/GPP_PROJECT_PROPOSAL_V0.md`

## 1. 门控定义（提案 §4.1）

- H1: 遗忘 ≤ E 的 50%（E=0.4555 → 0.2278），且新任务学习 ≥ 90%
- H4: 优化器 delta 投影是冻结参数的必要机制（仅梯度 hook 会漂移）

## 2. H4 结果（通过）

小模型 50 步 AdamW（lr=3e-4, wd=0.1），tok_emb 行 32-47 强制冻结：

| 冻结方式 | 冻结行最大 drift |
|---|---:|
| 仅梯度 hook（grad 置 0） | **9.94e-05**（权重衰减+动量穿透） |
| 优化器 delta 投影（scale=0） | **0.00e+00**（完全不可动） |

结论：梯度 hook 无法真正冻结参数——AdamW 解耦权重衰减与历史动量在梯度为 0 时仍移动权重。**优化器层投影是必要机制**（GPP 技术底座成立）。

## 3. H1 结果（机制有效，未稳定达标）

GPP = dense Transformer + 全参数逐行保护（include_ffn=True）+ 每任务预算 sticky 冻结（scale=0）+ 优化器投影。batch 32, 2000 步/任务。

| 种子 | 遗忘 | string final | modular final | 新任务(immediate) |
|---|---:|---:|---:|---|
| 1337 | **0.204** | 0.209 | 0.903 | 全部 1.0 |
| 42 | 0.355 | 0.0 | 0.616 | 全部 1.0 |
| 7 | 0.324 | 0.0 | 0.685 | 全部 1.0 |
| **平均** | **0.296** | 0.07 | 0.735 | 全部 1.0 |

参考基线（同口径）：A-dense 0.3984，E-sparse 0.4555。

### 3.1 关键发现

1. **scale=0（完全冻结）显著优于分级保护**：scale=0.1 → 0.3188；scale=0.05 → 0.259；scale=0 → 0.204（seed 1337）。分级保护下被保护行仍以 5-10% 速率漂移，累积起来仍破坏旧任务。
2. **新任务学习完整保留**：所有配置、所有种子下 immediate accuracy 全 1.0（冻结行不影响新任务使用新行）。
3. **不稳定来源是 modular**：modular 遗忘 0.097（1337）vs 0.38-0.39（42/7）。modular 与 shared 共享 NUMBER token 与加法规则——冻结 modular 行后 shared 用新行学习，但仍覆盖 modular 的未保护行。

### 3.2 调参验证（未改善）

| 配置 | seed 42 | seed 7 |
|---|---:|---:|
| budget=0.2, scale=0 | 0.3548 | 0.3244 |
| budget=0.4, scale=0 | 0.3308 | 0.3522 |

budget 增大不改善 modular 保留 → 不稳定非保护覆盖率问题，是**任务间 token 共享的结构性冲突**。

## 4. 结论

1. **机制有效性确认**：GPP 3 种子平均 0.296，比 A-dense 改善 26%、比 E 改善 35%。H4 证明其技术底座（优化器投影）必要且正确。
2. **H1 未稳定通过**：平均遗忘 0.296 > 门控 0.2278（差 30%），且 3 种子不稳定（0.204-0.355）。不满足"3 种子稳定"门控条件。
3. **根因**：任务套件 token 高度共享（string/unrelated 共享 SOURCE、modular/shared 共享 NUMBER、facts/conflict 共享 ENTITY），固定参数隔离类方法在该套件上存在结构性保护冲突——这与 FIP 攻坚的最终结论一致（`docs/FIP_PHASE0_FINAL_DECISION.md` §2.3）。

## 5. 下一步决策建议

M0 判定：**部分通过（H4 ✓，H1 ✗ 不稳定）**。继续投入前需二选一：

- **方案 A（推荐）：换任务套件重测 H1**。合成套件的 token 共享是已知的结构性问题（已有大量证据）。改用 token 分离的任务设计（如 Split MNIST / Split CIFAR，类别互斥、token/像素不共享），GPP 的隔离机制应能充分发挥。这是标准 CL 基准，也可直接进入提案 §4.2 阶段。
- **方案 B：接受 3 种子现状进入论文路径**。"遗忘降 35% + 新任务 100% 保留 + 优化器投影必要性"已是有价值的实证贡献，可作小论文（对比 EWC/PackNet 的机制分析），但不承诺达标。

建议先做方案 A 的快速验证（Split MNIST 或改造合成任务为 token 分离版，~1 天），若通过则 GPP 课题成立，进入 M1/M2。
