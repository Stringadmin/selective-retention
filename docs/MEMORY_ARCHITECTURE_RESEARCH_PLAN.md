# 研究方案：重要性驱动的 Agent 记忆写入与遗忘（Importance-Gated Memory）

> 日期：2026-08-18
> 状态：提案 v0.1（待评审）
> 来源：FIP/GPP 攻坚的方法论迁移 + 2026 记忆架构现状调研
> 一句话：**把 GPP 的"重要性驱动选择性保留"从参数空间搬到 Agent 记忆空间——学习"什么值得写入、什么该被遗忘"，解决现有记忆系统"要么全记要么乱删"的核心缺陷。**

## 0. 核心定位

2026 年 Agent 记忆系统（Letta/Mem0/Zep/LangMem）都是**工程框架**：它们回答了"怎么存、怎么取、怎么分层"，但回避了最根本的问题——**"什么值得写入记忆"**。

现状的两个极端都有缺陷：
- **LLM 自主决定**（Letta）：每次记忆操作都是 LLM 调用，贵、延迟高、且模型对"重要性"的判断不稳定。
- **启发式提取**（Mem0）：固定 prompt 提取"显著事实"，无法学习"哪类信息对未来真正有用"，也无真正的遗忘机制。

**本方案的核心主张**：记忆的写入、保留、遗忘应该是一个**可学习、可证伪、有理论依据的机制**，而不是 prompt 工程或人工规则。这正是持续学习中"重要性驱动保留"问题在记忆空间的翻版——我们在 FIP/GPP 上已经积累了这套方法论（重要性 EMA、选择性保留、优化器层执行）。

## 1. 与现有方法的差异点

| 对比对象 | 它们的做法 | 本方案的差异 |
|---|---|---|
| **Letta (MemGPT)** | LLM 通过工具调用自主管理记忆分页 | 用**学习到的轻量重要性评分**替代 LLM 逐条判断，写入成本从 O(LLM 调用) 降到 O(一次前向) |
| **Mem0** | 固定提取 prompt → ADD/UPDATE/DELETE/NOOP | 提取规则可学习，且引入**显式遗忘**（Mem0 的 DELETE 需外部触发，非内建衰减） |
| **Zep (Graphiti)** | 时序知识图谱，边带时间戳 | 图谱记"何时为真"，但不决定"值不值得记"。本方案是**写入闸门**，可与 Zep 的存储层正交组合 |
| **RAG / 长上下文** | 全量塞进向量库或上下文 | BEAM 已证 1M 窗口照样退化。本方案从**源头控制写入量**，而非事后检索 |
| **SleepGate / AgeMem / ENGRAM** | 睡眠周期遗忘 / 主动丢弃 / 潜空间压缩 | 这些处理"已存记忆的去留"，本方案管**写入这一刻的筛选**——上游闸门，与它们互补 |

**核心差异一句话**：现有系统优化"存取结构"，本方案优化"写入决策"——把记忆从"先全记再检索"变成"先筛选再存储"。

## 2. 方法定义（三层渐进）

### M1：重要性评分器（Importance Scorer）—— 核心
学习一个轻量函数 `score(turn, context) → [0,1]`，对每个候选记忆（对话轮、提取的事实）打分，决定是否写入。
- **信号来源**（借鉴 GPP 重要性 + 认知科学）：
  - 意外性（surprise）：该信息与现有记忆的预测误差（高意外 = 值得记）
  - 复用频率（reuse）：历史上类似信息被后续检索的次数（高复用 = 值得记）
  - 情感/任务显著性（salience）：与用户目标、偏好、约束的关联强度
- **实现**：小模型（或 LoRA 适配的 base LLM 头）做二分类/回归，成本远低于让主 LLM 逐条判断。

### M2：巩固与遗忘（Consolidation & Decay）—— 内建生命周期
- **巩固**：被反复检索/复用的记忆提升巩固度（consolidation strength），类比 CLS 理论中海马→新皮层的迁移。
- **遗忘**：遗忘曲线（ACT-R 式衰减）× 巩固度，低价值记忆随时间降权直至归档/删除。
- **关键**：遗忘是**内建、连续、可学习**的，不是 Mem0 那样的外部 DELETE 触发，也不是 Zep 那样永不删除只加时间戳。

### M3：参数化 vs 检索化记忆（可选，接 FIP 老本行）
- 研究"哪类知识该进权重（parametric，如稳定偏好/技能），哪类该外挂（retrieval，如临时事实）"。
- 这是 FIP"参数级知识固化"的直接延续，可作为论文的开放讨论章节。

## 3. 可证伪的核心假设

**H1（写入闸门有效性）**：在同等存储预算下，重要性驱动的选择性写入比"全量写入 + 检索"在长程任务上取得更高的事实准确率与更低的矛盾率。
**H2（遗忘必要性）**：引入内建遗忘机制的系统，在"知识更新 / 矛盾解决"类问题上显著优于"只增不删"的系统（BEAM 的 knowledge update / contradiction resolution 类别）。
**H3（学习优于启发式）**：学习到的 importance scorer 优于固定提取 prompt（Mem0 式）与 LLM 自主判断（Letta 式），且写入成本更低。
**H4（成本-质量帕累托）**：本方案在"每查询 token 数 / 延迟"与"准确率"的帕累托前沿上优于全量基线——即用更少记忆达到同等或更好效果。

## 4. 实验设计

### 4.1 阶段 0：基准与基线搭建（~2 周）
- **基准选择**（2026 现状）：
  - **LongMemEval**（主战场）：仍有区分度，专测知识更新、时间推理、多会话、拒答。
  - **BEAM**（压力测试，可选）：1M token 规模，验证"长上下文救不了长记忆"的论点。
  - ~~LoCoMo~~：已饱和（Mem0 92.5），只作回归检查，不作主证据。
- **基线**：full-context（暴力塞）、naive vector RAG、Mem0 式启发式提取、（若资源允许）Letta 式 LLM 自主管理。
- **底层 LLM 固定**（如 Qwen2.5 或同级开源模型），避免模型差异混淆记忆机制效果。

### 4.2 阶段 1：M1 写入闸门（~3 周）
- 实现 importance scorer，先在 LongMemEval 的对话历史上做**离线筛选**：给定全量对话，scorer 决定写入子集，再测检索+回答准确率。
- **核心对比**：同等记忆预算下，"重要性筛选写入" vs "全量写入" vs "随机写入" vs "Mem0 式提取写入"。
- 验证 H1、H3。

### 4.3 阶段 2：M2 遗忘机制（~3 周）
- 加入巩固度 + 遗忘曲线，重点测 BEAM/LongMemEval 的 **knowledge update** 与 **contradiction resolution** 类别（现有系统最弱处）。
- **核心对比**：有遗忘 vs 无遗忘（只增不删）在"事实被后续更新覆盖"场景下的表现。
- 验证 H2。

### 4.4 阶段 3：端到端 + 成本分析（~2 周）
- 完整系统跑 LongMemEval，报告准确率 + 每查询 token 数 + 延迟（2026 标准三指标），画帕累托前沿。
- 验证 H4。
- （可选）BEAM 1M 压力测试，对比"全上下文"在规模上的退化曲线。

## 5. 里程碑

| 里程碑 | 内容 | 判定 |
|---|---|---|
| M0（+2周） | LongMemEval 基线矩阵跑通 | full-context / RAG / Mem0 式基线数字可复现 |
| M1（+5周） | 重要性写入闸门 | H1/H3：同等预算下优于全量与启发式基线 |
| M2（+8周） | 遗忘机制 | H2：knowledge update / contradiction 类别显著优于只增不删 |
| M3（+10周） | 端到端 + 帕累托 | H4：成本-质量前沿占优，可出论文/长文 |

## 6. 风险与备选

| 风险 | 应对 |
|---|---|
| importance scorer 学不出有意义的信号 | 先用**弱监督**（复用频率/检索日志当标签）冷启动；退化为"多信号启发式 + 可调权重"也有价值 |
| 基准过难/过贵（BEAM 1M token 成本高） | 主战场锁定 LongMemEval（区分度足够），BEAM 只作可选压力测试或用小规模切片 |
| 与 Mem0/Letta 被审稿人视为"工程改进" | 论文重点突出"**可学习的写入决策 + 内建遗忘**"两个机制贡献，H2/H3 作差异证明，而非又一套存储框架 |
| 现有系统已隐含类似机制 | 调研已确认：现有系统均无"可学习的重要性写入闸门"，差异点成立（见 §1） |

## 7. 与 FIP/GPP 的切割与复用

- **方法论复用**：重要性驱动选择性保留（GPP 核心）、巩固与遗忘的生命周期管理、可证伪假设 + 阶段门控的研究范式。
- **工程资产**：本方案主体是新代码（记忆存储/scorer/评估），不依赖 FIP 代码库，但可复用其"重要性 EMA"的实现模式。
- **叙事连续性**：FIP（参数级知识固化）→ GPP（优化器级参数保护）→ 本方案（记忆级信息筛选）——一条"重要性驱动的选择性保留"主线，层层抽象。这条主线本身就是个能讲的故事。

## 8. 命名建议

- **IGM**: Importance-Gated Memory（重要性门控记忆）
- 备选：**SelMem**（Selective Memory）、**Consolidator**（强调巩固/遗忘）
