# FIP Phase 0 攻坚终局：证据汇总与课题决策

> 日期：2026-08-10
> 结论：FIP 特征隔离机制有实证价值（智能分配 25.7% vs 随机），但在此任务套件上无法达到协议门控。按预设转向其他课题方向。

## 1. 决定性实验矩阵（batch 32 官方口径，seed 1337，2000步/任务）

| 方案 | 遗忘 | vs E(0.4555) | 说明 |
|---|---:|---:|---|
| E 稀疏全量基线 | 0.4555 | — | 协议门控基准 |
| F 智能分配 | 0.5038 | -10.6% | FFN-only，失败 |
| F-random 随机分配 | 0.6782 | -48.9% | **智能分配比随机好 25.7%** |
| F + 累积非FFN保护(v1) | **0.3952** | **+13.2%** | 当前最佳，接近但仍未达标 |
| F + 累积保护 + token归属(v2) | 0.4548 | +0.2% | token 归属对共享 token 无效 |

**门控要求**：遗忘 ≤ 0.2278（比 E 降 50%）。最佳方案 0.3952，差距 73%。

## 2. 三个关键科学发现

### 2.1 智能特征分配有真实价值（架构不失去存在理由）
- F（importance 分配）0.5038 vs F-random（随机分配）0.6782 → **改善 25.7%**
- 注意：batch 16 加速口径只显示 8.7%，batch 32 官方口径才显现真实差异——此前加速验证险些误判

### 2.2 FFN 层隔离不是主要遗忘路径
- string 任务的 FFN 特征 100% 冻结（drift=0）后仍遗忘 → 泄漏在非 FFN
- drift 分析：unrelated 任务后 norm 是最大 drift 源（mean 0.0116），其次 embedding（0.0061）
- 非 FFN 保护（v1）是唯一实质降低遗忘的机制（0.5038→0.3952）

### 2.3 任务套件的 token 设计对 FIP 不利
- 6 个任务中，**除 query 标记外几乎所有 token 都是跨任务共享的**：
  - `SOURCE_BASE`(128-143) 被 string 与 unrelated 共享
  - `NUMBER_BASE`(64-79) 被 modular 与 shared 共享
  - `ENTITY_BASE`(32-47) 被 facts 与 conflict 共享
- token 归属保护（v2）只能冻结 query 标记（意义不大），共享 token 无法冻结（冻结会毁掉后续任务）
- **string 与 unrelated 共享输入 token 是数据设计的结构性困境**，纯参数保护机制无法解决

## 4. 课题决策建议

按预设（无法证明有效则转换课题）：

**可保留的资产**：
1. 智能分配 25.7% 优势的实证——可写成"特征级重要性分配在持续学习中的价值"小论文或章节
2. 累积式非 FFN 保护（v1，13.2% 改善）——独立方法候选
3. 完整的工程框架（双层 mask 优化器、状态机、回滚、消融框架）

**转换方向候选**（按可行性排序）：
1. **非 FFN 保护独立成课题**：以"importance 驱动的累积式参数保护"为核心，工程资产全部复用，实证支撑最强（13.2%）
2. **换任务设计重验**：把 string 与 unrelated 的 token 重叠作为实验缺陷修正后再测——但需评估是否值得（核心问题在数据设计而非机制）
3. **LoRA 变体**：D 组累积 LoRA 已有实现，但赛道拥挤
