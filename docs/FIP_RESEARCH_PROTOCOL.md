# FIP Research Protocol (Frozen v0.1)

> 冻结日期：2026-07-29
> 状态：第一阶段协议冻结，未经显式变更审批不得修改本文件中的指标与门槛。

## 0. 总命题

在固定参数量、预训练 token、持续学习数据和优化步数下，FIP 能否在不依赖推理任务 ID、经验回放和独立 LoRA 的情况下，将灾难性遗忘相对普通 Transformer 降低 >=50%，同时保持新任务学习效果 >= 普通微调的 95%？

最终论文级目标：遗忘降低 >=75%。第一阶段以 50% 作为继续投入门槛。

## 1. 公平性规则（必须提前冻结）

冻结以下变量，所有实验组保持一致：

- 最大参数量
- 激活参数量
- 训练 token
- 优化步数
- 学习率搜索次数
- 数据顺序
- 随机种子
- 检查点和评测脚本哈希

报告两种公平口径：

1. 等 token、等步骤
2. 等 FLOPs 或等墙钟时间

> 说明：初版使用稠密 GPU 算子模拟 Top-K，实际速度可能更慢。初期只验证科学机制，不宣称推理加速。

## 2. 实验组（第一阶段完整矩阵）

| 组别 | 架构 | 更新方式 | 目的 |
|---|---|---|---|
| A | 普通 Transformer | 全参数微调 | 主基线 |
| B | 普通 Transformer | EWC | 传统防遗忘基线 |
| C | 普通 Transformer | 5% Replay | 经验回放强基线 |
| D | 普通 Transformer | 累积 LoRA | 参数隔离基线 |
| E | Top-K 稀疏 FFN | 全参数微调 | 测"只有稀疏"是否有效 |
| F | FIP | 特征分配+梯度隔离 | 完整架构 |

关键归因：

- A->E：稀疏激活本身的作用
- E->F：特征可塑性管理的增量
- A->B/C/D：现有持续学习方案
- C->F：FIP 能否在不保存旧数据的情况下接近或超过 Replay

### LoRA 报告口径

- 累积并合并 LoRA：不提供任务 ID，公平比较
- 每任务独立 LoRA：提供任务 ID，只作为理想上限，不与 FIP 直接宣称胜负

## 3. 三阶段验证

### Phase 0：机制验证

模型配置：

```
参数量：10M-20M
层数：6
hidden size：256
context：256
feature width：1024
Top-K：64
free slots：20%
```

数据：可完全控制的合成任务

1. 关联事实记忆：实体->属性->答案
2. 冲突事实更新：同一实体的新旧版本
3. 组合规则：模运算、字符串变换
4. 共享能力：不同任务复用同一底层规则
5. 无关任务：检测误伤

通过门槛：

- stable 特征梯度泄漏接近 0
- 删除某次更新后，模型 logits 恢复误差 < 1e-6
- 死亡特征比例 < 20%
- FIP 遗忘至少比稀疏全量微调低 50%
- 新任务学习能力不低于普通微调 90%

预算：约 4-12 GPU 小时，5 个随机种子。

> 如果 Phase 0 失败，不进入自然语言预训练。

### Phase 1：50M 自然语言模型

配置：

```
参数量：约 50M
层数：8
hidden size：512
heads：8
context：512
vocab：32K
FFN width：2048
Top-K：128
free slots：20%
精度：BF16
```

基础预训练：

- 约 5 亿 token
- FineWeb-Edu 固定采样
- Dense 与 FIP 分别从头训练
- 相同 token、优化器、学习率搜索预算和随机种子
- 保存数据清单、文件哈希和样本顺序

持续学习流（依次）：

1. 通用对话
2. Python/代码
3. 数学
4. 生物医学
5. 法律文本
6. 新事实更新集

每个领域准备独立训练集、验证集、保留测试集，禁止后续任务混入旧任务数据。Replay 组除外，但必须明确记录 5% 的旧数据预算。

Phase 1 门槛：

| 指标 | 继续条件 |
|---|---:|
| 基础困惑度相对 Dense | 恶化 <=5% |
| 平均遗忘相对 Dense | 降低 >=50% |
| 新任务效果 | >= Dense 全量微调的 95% |
| 无关任务误伤 | <= 2pp |
| 更新特征比例 | <= 10%，目标 1-5% |
| 推理延迟增加 | <= 15% |
| 推理任务 ID | 不允许 |

先跑 1 个种子。通过后再补 3 个种子和置信区间。

预计单种子完整矩阵约 2-5 个 GPU 日；实际时间必须先用 100 万 token 吞吐基准重新计算。

### Phase 2：100M-300M 放大验证

只有 Phase 1 通过才执行。

目标：

- 1B-2B 预训练 token
- 上下文提升到 1024
- 使用正式持续学习基准（TRACE 及自建事实更新集）
- 至少 3 个随机种子
- 增加 SAE-FD 复现基线
- 测量学习 10-20 个连续领域后的容量耗尽情况

论文级通过标准：

- 遗忘相对 Dense 降低 >=75%
- 平均旧任务下降 <= 2pp
- 新任务能力 >= 普通微调 95%
- 不使用旧数据回放
- 不需要推理任务 ID
- 推理延迟增加 <= 10%
- 结果在 3 个种子上稳定

## 4. 核心指标

训练完任务 `i` 后，在任务 `j` 上的成绩记为 `A_ij`。

必须报告：

- Average Accuracy
- Average Forgetting
- Backward Transfer
- Forward Transfer
- 新任务可塑性
- 每个任务激活的特征集合
- 不同任务特征 Jaccard 重叠率
- stable/shared/plastic/free 数量变化
- 实际修改的权重比例
- tokens/s、峰值显存、首 token 延迟
- 特征回滚后的输出恢复误差

## 5. 关键消融实验

完整 FIP 有效后，依次移除：

1. 去掉 Top-K
2. 去掉 stable 冻结
3. 去掉 free 特征池
4. 去掉 shared 状态
5. 随机分配特征，而不是按重要性
6. 所有特征都允许更新
7. 不做任务结束后的固化
8. 只冻结 FFN，不使用稀疏特征

> 如果"随机冻结"与 FIP 效果接近，说明智能特征分配没有价值。
